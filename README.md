# Courier Route

Навчальний планувальник короткого маршруту одного кур'єра на координатній площині: склад → усі точки доставки → склад. Координати й одиниці довжини умовні. Майбутній ітеративний пошук повертатиме найкращий знайдений маршрут без гарантії глобальної оптимальності.

У **блоці 1** працюють українська стартова сторінка, справжня перевірка доступності Express та віддавання зібраного клієнта тим самим сервером. Алгоритм, PostgreSQL, авторизація, задачі, черга, схема маршруту, HTTPS, балансування, масштабування й адмінпанель ще не реалізовані. План усіх 10 блоків і матриця вимог — у [PROJECT_PLAN.md](PROJECT_PLAN.md); фактичні результати — у [звіті блоку 1](docs/block-01-report.md).

## Оточення

- Node.js **24.x LTS**, npm **11.x**. Сумісність обмежена цими гілками в `package.json`; `.nvmrc` містить `24`. Перевірено на Node.js 24.18.0 і npm 11.16.0, macOS arm64.
- Гілка Node.js 24 залишається підтримуваною за [офіційним графіком релізів](https://github.com/nodejs/Release/blob/main/schedule.json). Vite підтримує Node.js 20.19+ / 22.12+; обрана 24.x задовольняє [його вимоги](https://vite.dev/guide/).
- Вільні локальні порти 3000 (Express) та 5173 (Vite у dev). Docker, Kubernetes, PostgreSQL і Traefik для блоку 1 не потрібні.
- Доступ до npm registry для першого встановлення. Глобальні пакети встановлювати не потрібно.

## Встановлення й локальна розробка

Виконуйте з кореня проєкту:

```sh
npm install
npm run dev
```

Відкрийте **http://127.0.0.1:5173/**. Vite проксіює `/api` на Express; прямий health: **http://127.0.0.1:3000/api/health**. Зміни клієнта підхоплює Vite, сервер перезапускає вбудований Node watch із `tsx`. `Ctrl+C` завершує обидва процеси.

Локальний `.env` необов'язковий. Без нього Node виводить повідомлення й використовує порт 3000. За потреби:

```sh
cp .env.example .env
```

У `.env` є лише `PORT=3000`. Після зміни порту перезапустіть dev: Express і проксі Vite прочитають спільне значення. Допустимі цілі значення — від 1 до 65535; порт має бути вільним. Vite залишається на 5173. Змінна `PORT` процесу має пріоритет над `.env`. Обидва сервери слухають лише `127.0.0.1`.

## Перевірка, збирання та запуск

```sh
npm run typecheck
npm run build
npm start
```

Відкрийте **http://127.0.0.1:3000/**. У зібраному режимі сторінку, CSS/JS та API віддає Express з одного походження; Vite не потрібен. Це локальний HTTP-запуск; HTTPS заплановано в блоці 7.

`typecheck` перевіряє сервер, клієнт, shared і конфігурацію Vite зі strict-налаштуваннями. `build` очищує `dist`, компілює backend і shared через TypeScript, потім збирає frontend через Vite. `start` потребує виконаного `build`. `Ctrl+C` коректно закриває HTTP-сервер; граничний час завершення — 5 секунд.

Ручна HTTP-перевірка після запуску:

```sh
curl -i http://127.0.0.1:3000/api/health
curl -i http://127.0.0.1:3000/
curl -i http://127.0.0.1:3000/api/not-found
```

Очікувано: `200 application/json` із `status: "ok"` та непорожнім `instanceId`, `200 text/html`, `404 application/json`. `instanceId` створюється раз на запуск і різниться між процесами. Health перевіряє лише доступність цього процесу; БД ще немає. Сторінка показує результат реального `fetch('/api/health')`; при HTTP-помилці, некоректній відповіді чи недоступності протягом 5 секунд показує повідомлення про недоступність. Браузерну перевірку в цьому середовищі не виконано через відсутність підключеного браузера.

## Структура

```text
src/
  server/index.ts       Express, health, static, 404, завершення
  client/              Українська сторінка, стилі, перевірка health
  shared/health.ts      Спільний тип HealthResponse
scripts/clean.mjs       Очищення лише каталогу dist
docs/assignment.txt    Дослівний оригінал вимог викладача
docs/block-01-report.md Фактичний звіт блоку 1
PROJECT_PLAN.md         Архітектура, 10 блоків, матриця вимог
AGENTS.md               Постійні інструкції та Git-правила
```

Проєкт використовує ESM (`type: module`). Backend — `NodeNext`, відносні TypeScript-імпорти мають розширення `.js`, збирання зберігає структуру: `src/server` → `dist/server`, `src/shared` → `dist/shared`; клієнт потрапляє в `dist/client`. Шлях static обчислюється від `import.meta.url`, а не від поточної робочої папки. Майбутні worker-файли належатимуть `src/server` і так само збиратимуться в `dist/server`; зараз їх немає.

## Залежності

Прямі версії зафіксовані точно, транзитивні — у `package-lock.json`.

| Пакет | Версія | Призначення |
| --- | --- | --- |
| express | 5.3.0 | HTTP API та статичні файли |
| typescript | 7.0.2 | Типи й компіляція backend |
| vite | 8.3.5 | Збирання клієнта, dev і проксі |
| tsx | 4.23.15 | Запуск TypeScript у dev |
| concurrently | 10.0.6 | Спільний запуск і завершення dev-процесів |
| @types/express | 5.0.6 | Типи Express |
| @types/node | 24.19.2 | Типи Node.js 24 |

У production потрібен Express і його транзитивні залежності. Решта — інструменти розробки та збирання. `pg` та інфраструктурні залежності додаються у відповідних наступних блоках.

## Git

Локальний репозиторій створено в корені проєкту, основна й поточна гілка — **main**. Remote і push не налаштовано. Після завершених логічних змін створюються коміти з короткими англійськими назвами `type(scope): description` (scope необов'язковий), наприклад `feat(server): add health endpoint`.

Перед комітом перевіряються status, звичайний і staged diff та доречні перевірки. Повні постійні правила — у [AGENTS.md](AGENTS.md). `.gitignore` виключає `node_modules`, `dist`, логи та локальні `.env`; `.env.example` і lock-файл відстежуються. Дослівні вхідні тексти захищені від перетворення кінців рядків у `.gitattributes`.

Блок 2 починається лише після перевірки результату керівником і нового завдання.
