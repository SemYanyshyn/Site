## 3. Сценарій і введення

Реєстрація → окремий вхід → завантаження `/api/jobs/limits` → склад X/Y → доставки → бюджет/seed → «Знайти маршрут». До завантаження коректних лімітів запуск вимкнений. Власні серверні межі не замінюються вигаданими клієнтськими.

Склад початково `(0, 0)`. Кожен непорожній рядок доставок — рівно два скінченні числа `x y`, розділені пробілом/табуляцією, дроби з крапкою. Parser повідомляє фізичний номер поганого рядка, перевіряє повний числовий токен, модуль координат, число доставок, додатний цілий бюджет, unsigned seed. Однакові доставки зберігаються окремо; одна доставка допустима. Перед побудовою структур обмежуються довжина тексту й кількість рядків.

Початковий бюджет — `min(1000000, maxIterations)`. Порожній seed відсутній у POST, фактичний генерує сервер; `0` надсилається явно. «Заповнити квадрат» тільки заповнює форму. Помилка не стирає введення.

## 4. API, polling, cancel і гонки

Усі шляхи відносні `/api/...`, cookies — same-origin, cache — no-store, запити мають кінцевий timeout 10 с та abort. POST має JSON Content-Type; Origin надсилає браузер. Відповіді перевіряються як `unknown`, включно з id, лічильниками, pagination, completed input/result і порядком маршруту.

Прапорець pending синхронно блокує подвійний POST. Мережевий збій або невалідна успішна відповідь створення показує: **«Запит міг бути прийнятий. Оновіть історію перед повторним запуском»**. Автоматичного повтору немає. Особиста квота, загальна місткість і недоступність БД зберігають різні серверні code/message.

Один керований цикл читає active/history та потрібні деталі; наступний timer через 1000 мс після читання. Refresh coalesce, однойменні читання не накладаються. Active дочитується максимум двома сторінками по 50, що покриває настроювану квоту 100. Terminal detail автоматично більше не опитується; інші активні задачі продовжують оновлюватися. Після мережевої помилки/503 останні дані залишаються з помилкою й можливістю повторного читання.

Cancel надсилає `{}`. Running/202/cancelRequested показує очікування зупинки, а не cancelled; terminal підтверджується наступним читанням. Completed у гонці відображається як completed. Під час pending cancel кнопки скасування заблоковані з поясненням. Покоління сеансу, вибору та сторінки разом з abort захищають усі limits/list/detail/create/cancel відповіді; старий GET не стирає прийнятий cancel.

## 5. Сеанс та історія

UI відкривається лише після login або підтвердженого `/me`. Logout-success і jobs/401 очищують чернетку, списки, деталі, метадані, SVG, таймери та запити. 503 не оголошує сеанс завершеним. Cookie/токен не читається JavaScript, приватні дані не записуються в localStorage.

Reload відновлює сеанс та читає БД без нового POST. Вихід/закриття сторінки не скасовує прийняту job. Історія власника має сторінки по 20, попередню/наступну без вигаданого total. Виявлено й виправлено помилку: після 503 нової сторінки старі рядки мали новий номер; тепер зберігається номер останньої успішної сторінки, повторний перехід працює й має регресійний тест.

## 6. Збережений результат і геометрія

SVG будується виключно за runtime-перевіреними saved input/result для completed, незалежно від поточної чернетки. Індекси: склад `0`, доставки `1..N`, повернення до `0`; перевіряється точна перестановка та евклідова довжина. В UI показано початкову й найкращу довжину в умовних одиницях, seed, бюджет/фактичні ітерації, час **алгоритму**, причину завершення. Наближений пошук не доводить глобальну оптимальність.

Рівний масштаб X/Y, padding, viewBox, інверсія Y вгору; склад — квадрат, доставки — кола з номерами. Для понад 40 точок зберігаються всі маркери, текстовий порядок і збережені координати доступні окремо. Збіги можуть накладатися, що прямо пояснено. Вироджені X/Y, збіжні точки й дуже малі проміжки не дають NaN/Infinity. Додатково виправлено округлення малої ненульової довжини до 0: використовується scientific notation. Trivial/zero_length з 0 ітерацій показується без удаваної роботи; running 99.999 не стає 100%.

DOM використовує textContent та числові SVG-атрибути, без вставлення API-даних через innerHTML. Форми статичні, polling зберігає фокус/курсор. Незмінні live-повідомлення не переписуються кожного циклу.

Реальна браузерна перевірка додатково знайшла dev-помилку: proxy-префікс `/api` перехоплював `/api.ts`, модуль повертав 404 й UI не запускався. Правило звужено до `^/api(?:/|$)`. Регресія перевіряє JavaScript-вміст `/api.ts`, збережено перевірку справжніх API/Origin; повторні typecheck/build, усі 13 auth PG та 14 browser груп пройшли.
