# Мої нотатки до клієнтського коду

05.11.2026: у всіх 15 файлах src/client/*.ts додано українські пояснення від першої особи до основних блоків. Наявні англомовні пояснення перекладено; службову директиву reference types="vite/client" збережено.

## Де що шукаю

| Файл у src/client | За що відповідає |
| --- | --- |
| main.ts | Запуск клієнта, зв’язок форм із контролерами, вхід/вихід і життєвий цикл сторінки |
| auth-ui.ts | Форма реєстрації та входу, перевірка сесії, показ пароля, вихід |
| api-endpoint.ts | Спільна адреса API та правила передавання cookie |
| api.ts | Запити до особистих задач і повідомлення про помилки |
| jobs-controller.ts | Стан задач на екрані, оновлення, вибір, історія, створення та скасування |
| jobs-view.ts | HTML форми, списків, деталей, прогресу та результату |
| route-input.ts | Перевірка тексту форми й перетворення його на числові дані |
| response.ts | Перевірка JSON задач, результатів, черги й лімітів із сервера |
| route-geometry.ts | Координати готового маршруту для SVG і форматування прогресу |
| initial-route.ts | Послідовність і таблиця переходів збереженого початкового маршруту |
| queue-display.ts | Текст приблизного очікування в черзі та основа серверної оцінки |
| admin-api.ts | Запити читання огляду моніторингу й загального списку задач |
| admin-controller.ts | Стан адмінпанелі, автооновлення, роль, фільтр і сторінки |
| admin-response.ts | Перевірка даних БД, pod, процесів, метрик і HPA для адмінпанелі |
| admin-view.ts | HTML карток серверів, зведення, станів джерел і списку задач |

Для особистих задач іду від main.ts до jobs-view.ts та jobs-controller.ts, а далі до api.ts і response.ts. Для адмінпанелі використовую таку саму послідовність admin-view → admin-controller → admin-api → admin-response. Вхід зосереджений в auth-ui.ts, а адреса всіх запитів — в api-endpoint.ts.

## Що перевірено

- Змінено лише коментарі; код і його форматування збережено.
- Esbuild-порівняння всіх 15 файлів до/після дало однаковий виконуваний JavaScript.
- npm run typecheck та npm run build — PASS.
- npm run test:client — 66 PASS, без помилок і пропусків.
- git diff --check — PASS.
- Нових тестів, залежностей або функцій не додано. Deployment, тунелі й робочу базу не перезапускали.


## Де шукаю оформлення — SCSS

05.11.2026: додав такі самі українські нотатки від першої особи до основних блоків усіх восьми SCSS-файлів.

| Файл у src/client | Що тут змінюю |
| --- | --- |
| styles.scss | Порядок підключення всіх модулів через @use |
| styles/_tokens.scss | Шрифти, межі екранів, кольори, тіні та заокруглення |
| styles/_base.scss | Базовий текст, HTML-елементи, hidden, фокус і зменшення анімації |
| styles/_layout.scss | Шапку, вступ, робочі колонки, навігацію та підвал |
| styles/_components.scss | Спільні кнопки, поля, картки, повідомлення, мітки станів і прогрес |
| styles/_auth.scss | Картку входу, реєстрацію, поле пароля й рядок користувача |
| styles/_jobs.scss | Форму маршруту, чергу, деталі, SVG, таблицю переходів і списки задач |
| styles/_admin.scss | Зведення адмінпанелі, джерела даних, картки серверів, ресурси та задачі |

Мобільні правила шукаю в кінці відповідного модуля у @media. Межі ширини задані в _tokens.scss: tablet 1100 px, stack 800 px, phone 600 px. Змінні $ використовую під час компіляції SCSS, а змінні -- доступні браузеру через var(...).

Перевірив, що всі рядки правил без коментарів дослівно збережено, а скомпільований CSS кожного з восьми файлів побайтово збігається з початковим, включно з головною збіркою styles.scss. Typecheck/build і git diff --check пройшли. Вигляд і поведінка сторінки не змінилися; нові тести не додавалися, браузер та deployment для цього доручення не перезапускалися.
