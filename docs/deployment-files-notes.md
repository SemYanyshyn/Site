# Коротко про deployment-файли

| Файл | Призначення |
| --- | --- |
| deploy/k8s/app.json | Запуск серверів застосунку та внутрішній доступ до них. |
| deploy/k8s/config.json | Спільні налаштування, ліміти задач і черги. |
| deploy/k8s/hpa.json | Автоматичне масштабування застосунку від 2 до 4 копій за CPU. |
| deploy/k8s/ingress.json | Правила передавання HTTPS-запитів до застосунку. |
| deploy/k8s/metrics-server.json | Збір CPU/RAM для HPA та моніторингу. |
| deploy/k8s/migrate.json | Одноразове завдання міграцій бази даних. |
| deploy/k8s/monitor-rbac.json | Права читання Kubernetes для адмінпанелі. |
| deploy/k8s/namespace.json | Окремий простір ресурсів проєкту. |
| deploy/k8s/postgres.json | PostgreSQL, внутрішній доступ і збереження даних у PVC. |
| deploy/k8s/traefik.json | Вхідний HTTPS-проксі та розподіл запитів між серверами. |
| deploy/kind-config.json | Створення локального кластера kind і зіставлення його портів. |
| deploy/versions.json | Закріплені версії інструментів та точні образи. |

04.11.2026 додано від одного до трьох коротких українських пояснень у кожен новий файл. Попередні докладні пояснення kind-config.json скорочено до п’яти основних. Нотатки від першої особи збережено в службових JSON-полях _comment та _comment_*.

scripts/deployment-config.mjs прибирає нотатки перед використанням вихідних конфігурацій. На нього переведено читання versions/kind/k8s у deploy-local.mjs та versions у check-container.mjs; звичайне читання файлів стану/секретів не змінено. Попередній kindConfigWithoutNotes збережено як сумісний експорт.

Перевірка всіх 12 файлів: очищені значення, типи та порядок серіалізації точно збігаються з початковими. Окремо перевірено вкладені нотатки, масиви, false/0/null, звичайні ключі міток і старий експорт. Native syntax, імпорт deployment helper, typecheck/build, 51 unit та 15 non-DB admin перевірок — PASS. Кластер, контейнери, міграції й робоча БД для цього завдання не запускалися.

У перевірочному скрипті уточнено відбір ресурсу Role, щоб не плутати його з kind у roleRef; також виправлено копіювання очікуваного об’єкта перед порівнянням. Фінальне порівняння всіх конфігурацій пройшло; помилки тимчасового інструмента не видавалися за дефекти Kubernetes.

Попередні й паралельні редагування Dockerfile, форматування deploy-local.mjs та app.json збережено в робочій папці поза комітом.
