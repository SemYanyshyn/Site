# Адміністративний моніторинг

Тут збираю read-only огляд задач, виконавців і справжньої інфраструктури

Вхід із роллю user не дозволяє адміністративні запити — роль admin щоразу перевіряю в базі

Pod — одиниця запуску контейнера в Kubernetes, Deployment керує репліками, HPA змінює їх кількість за метриками

Цей код читає їхній стан, але не масштабує та не видаляє ресурси

ServiceAccount надає обмежений доступ до API Kubernetes, CA перевіряє TLS, а застарілі метрики позначаю явно

## Моя мапа файлів

- [`config.ts`](config.ts) — задаю часові та розмірні межі адміністративного моніторингу
- [`auth.ts`](auth.ts) — перевіряю право доступу до адміністративного API
- [`budget.ts`](budget.ts) — обмежую час читання адміністративних даних і реагую на скасування запиту
- [`router.ts`](router.ts) — описую read-only HTTP-маршрути адміністратора для огляду інфраструктури та списку задач
- [`repository.ts`](repository.ts) — читаю адміністративний огляд із PostgreSQL без зміни даних
- [`kubernetes.ts`](kubernetes.ts) — читаю справжні pod, HPA, Deployment і метрики через HTTPS API Kubernetes
- [`service.ts`](service.ts) — об’єдную дані PostgreSQL і Kubernetes у модель адміністративного екрана

Докладні пояснення основних блоків залишаю безпосередньо в коментарях відповідних файлів
