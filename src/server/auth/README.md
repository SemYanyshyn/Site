# Вхід і сесії

Тут розбираюся, як сервер реєструє користувача, перевіряє пароль і впізнає його наступні запити через cookie

Для себе розділяю автентифікацію — хто зробив запит — і авторизацію — що цьому користувачу дозволено

Пароль проходить scrypt, випадковий токен сесії зберігається в HttpOnly cookie, а його хеш і строк дії — у PostgreSQL

Маршрути починаються з `/api/auth`, перевірка поточної сесії — `GET /api/auth/me`

## Моя мапа файлів

- [`errors.ts`](errors.ts) — описую безпечні помилки API з HTTP-статусом, кодом і зрозумілим повідомленням
- [`password.ts`](password.ts) — працюю з паролями через scrypt, а не зберігаю сам пароль у PostgreSQL
- [`middleware.ts`](middleware.ts) — перевіряю автентифікацію перед захищеним API, тобто визначаю хто саме зробив запит
- [`router.ts`](router.ts) — описую HTTP-маршрути реєстрації, входу, перевірки сесії та виходу
- [`sessions.ts`](sessions.ts) — пов’язую браузерну cookie із сесією в PostgreSQL

Докладні пояснення основних блоків залишаю безпосередньо в коментарях відповідних файлів
