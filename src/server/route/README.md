# Обчислення маршруту

Тут виконую перевірку входу, пошук маршруту й керування окремим worker-потоком

Worker thread — це потік усередині Node.js-процесу, який рахує маршрут, поки головний потік відповідає на HTTP

Один RouteExecutor має один слот, а спільна черга між серверами зберігається в PostgreSQL у шарі jobs

Алгоритм працює з умовними координатами та евклідовою відстанню, повертає найкраще знайдене наближене рішення

Цей шар не потребує бази для окремого запуску `npm run route:demo`

## Моя мапа файлів

- [`config.ts`](config.ts) — обмежую розмір задачі та час роботи алгоритму, щоб один запит не забрав усі ресурси
- [`validation.ts`](validation.ts) — перевіряю невідомі вхідні дані перед копіюванням і створенням worker
- [`algorithm.ts`](algorithm.ts) — виконую сам математичний пошук маршруту в окремому worker-потоці
- [`executor.ts`](executor.ts) — керую життєвим циклом одного worker-потоку цього серверного процесу
- [`worker.ts`](worker.ts) — точка входу окремого потоку, який виконує важкий пошук і не обробляє HTTP
- [`dev-worker.mjs`](dev-worker.mjs) — маленький завантажувач worker для запуску TypeScript під час розробки
- [`random.ts`](random.ts) — створюю відтворюваний генератор псевдовипадкових чисел для алгоритму
- [`examples.ts`](examples.ts) — готую вхідні координати для автоматичних тестів і вимірів продуктивності
- [`cli.ts`](cli.ts) — Цим файлом запускаю розрахунок маршруту з термінала без HTTP і PostgreSQL
- [`bench.ts`](bench.ts) — Цим файлом вимірюю справжній час, CPU і пам’ять пошуку на кількох розмірах входу

Докладні пояснення основних блоків залишаю безпосередньо в коментарях відповідних файлів
